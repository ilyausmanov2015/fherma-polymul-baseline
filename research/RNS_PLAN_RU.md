# Кандидат: точная свёртка через малые простые и CRT

Это проект следующего эксперимента, не реализованный и не измеренный результат.
Текущие задержки CPU/GPU сначала измеряются отдельно. На 17 сентября лучший
полный конкурсный результат — 951,667 мкс, 20/20; короткий вариант — 747 мкс.

## Точность

Входы канонические: 0 <= a_i,b_i < q. Коэффициент целочисленной
негациклической свёртки ограничен по модулю N*(q-1)^2. Выбираем разные простые
p_i < 2^31, p_i = 1 mod 65536, пока P=product(p_i) > 2*N*(q-1)^2.
Ожидается 57 простых около 2^31; число и неравенство обязательно проверить
целочисленно. Нельзя брать только 28–29 простых: этого недостаточно для
восстановления произведения, даже если выход имеет 868 бит.

NTT выполняется независимо по каждому p_i с корнем psi порядка 2N.
Балансированный CRT-результат c_Z в (-P/2,P/2) совпадает с точной свёрткой.
Финальный ответ — c_Z mod q. Никаких предположений о случайности входов.

## Малые модульные операции

Для постоянного twiddle w хранить w и floor(w*2^32/p). Shoup-умножение:
t=umulhi(x, w_shoup), r=low32(x*w-t*p); при 0<=x,w<p<2^31 имеем r<2p,
поэтому достаточно одного вычитания p. Сумма двух остатков также <2^32.
Для произвольного поэлементного произведения нужен Barrett или эквивалентная
полная 64-битная редукция, а не неподходящий Shoup от другого операнда.

Входной 896-битный ABI преобразовать по Horner из 28 слов. Постоянный
2^32 mod p имеет собственный Shoup-множитель; каждое входное слово приводится
к p не более чем двумя вычитаниями для выбранных p>2^30.

## CRT без деления широких чисел на GPU

Mi=P/pi, ti=(ri * inverse(Mi mod pi)) mod pi. S=sum(ti*Mi)<57P.
При 57 выбранных 31-битных простых S помещается в 56 слов (1792 бита);
это также проверяется в setup. Хранить Mi по словам в constant memory,
накапливать S в регистрах одного потока на выходной коэффициент.

Для alpha=floor(sum(ti/pi)) использовать заниженную fixed-point оценку:
alpha0 = high64(sum(ti * floor(2^64/pi))). Каждое отдельное произведение
помещается в 64 бита; у суммы отдельно учитываются переносы.
Ошибка меньше sum(ti)/2^64 < 57*2^31/2^64 < 1, поэтому alpha0 отличается
от alpha максимум на единицу вниз. Вычесть alpha0*P из S и, если остаток
>=P, ещё один раз P. Это даёт точный канонический CRT без floating point.

Сравнить остаток с P/2. Редуцировать его по q=2^868-c двумя сворачиваниями
с полноценным промежуточным буфером (первое значение шире 896 бит!).
Для отрицательного балансированного значения дополнительно вычесть P mod q.
Нельзя применять существующее 896-битное промежуточное хранилище первого
fold к 1767-битному CRT: его старшая часть после умножения на c шире 896.
При указанных размерах первый fold помещается в 29 слов, второй — в 28;
финальное условное вычитание q обеспечивает каноничность.

## GPU-раскладка

Буферы [prime][coefficient], пары прямых NTT совместно. Первые 10 стадий
можно объединить в плитке 1024 uint32 (4 КиБ shared), затем транспонировать
матрицу 32x1024 и объединить последние 5 стадий. Таблицы корней также должны
соответствовать новой раскладке. Исследовать число колонок на блок и потоки.
Существующий опыт показывает, что сокращение числа kernels само по себе
не гарантирует ускорения: разрозненные чтения корней могут съесть выигрыш.

Все преобразования входов, CRT, копирования и создание ответа остаются внутри
измеряемого run. В setup доступны только параметры, корни, таблицы и пустые
буферы. Сначала проверить правила конкурса насчёт обязательности cuPQC;
публичная карточка лидера указывает CUDA, но одной метки для вывода недостаточно.
