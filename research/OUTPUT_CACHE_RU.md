# Проверка стоимости согласования CPU cache при D2H

Наблюдение: в диагностике 7 MiB H2D занимают около 138 мкс,
а 3.5 MiB D2H — около 97 мкс. Это измеренная асимметрия, не доказательство
конкретного ограничения. Проверяется гипотеза, что строки staging-выхода,
прочитанные CPU в предыдущем вызове, увеличивают стоимость следующей DMA.

После копирования своей части результата worker выполняет CLFLUSHOPT
только для целых 64-байтных строк внутри этой части staging-буфера, затем
SFENCE до публикации завершения. Выходной vector не сбрасывается. Все
расходы входят в run. Между вызовами сохраняется только обычный рабочий
буфер; его содержимое всегда перезаписывается новым вычислением.
На CPU без CLFLUSHOPT функция ничего не делает. Это эксперимент:
стоимость самих flush может перевесить любую экономию следующей DMA.

Portable проверки: 650 вариантов копирования с невыровненными границами,
1050 заданий пула. Реальная инструкция проверяется в x86 CI и на runner.
Семантика CLFLUSHOPT и SFENCE: Intel Optimization Reference Manual, 9.4.7:
https://cdrdv2-public.intel.com/814198/248966-Optimization-Reference-Manual-V1-049.pdf
