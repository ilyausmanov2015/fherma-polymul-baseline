# H2D и prepare в графе одной части

FHERMA_INPUT_COPY_GRAPH использует четыре отдельных графа. Каждый содержит
один H2D для смежных A/B своей части и следующую за ним prepare_grouped.
CPU запускает граф только после завершения всех worker copies этой части
и SFENCE публикации write-combined входа. Поэтому GPU никогда не читает
частично заполненную область. Части имеют непересекающиеся staging/GPU
диапазоны; следующая часть может заполняться во время работы предыдущего
графа. Графы и основная NTT идут по одному stream в порядке запуска.

В run одна GraphLaunch заменяет memcpy, record, wait и prepare GraphLaunch.
В отличие от прежних transfer graphs, внешние межпоточные события здесь
не нужны. Цена — H2D следующей части начинается после prepare предыдущей:
раздельные GPU-потоки передачи/вычислений на этом пути не используются.
Измерение должно сравнить экономию CPU enqueue с потерей этого overlap.

В init выполняются только capture/upload и заполнение пустых буферов;
входные данные каждого run копируются заново. Размеры используют тот же
paired layout, что и обычный staged pipeline. Для N вне быстрого пути
сохраняются прежние отдельные memcpy и универсальная подготовка.
Флаг несовместим с mapped input и единым input-readiness graph.
