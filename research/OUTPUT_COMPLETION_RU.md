# Уведомление CPU через stream memory operations

Эксперимент FHERMA_OUTPUT_SIGNAL заменяет восемь output events на
cuStreamWriteValue32 после соответствующих D2H в том же CUDA stream.
Флаги занимают отдельные 64-байтные строки mapped pinned memory.
CPU acquire-load проверяет номер текущего запуска. Все данные результата
копируются только после готовности своей части; функция возвращается после
копирования всех частей. Переполнение unsigned generation безопасно: перед
новым запуском каждый флаг содержит номер предыдущего завершённого запуска.

DEFAULT включает fence предшествующих записей с системной видимостью.
NO_MEMORY_BARRIER не используется. GPU не ждёт CPU через флаги, зависимости
между CUDA задачами остаются выражены порядком операций в одном stream.
После 131072 итераций CPU выполняет обычную синхронизацию stream, чтобы
получить асинхронную ошибку вместо бесконечного ожидания. Если stream завершён,
а флаг не обновлён, выполнение завершается ошибкой, а не выдаёт старые данные.

init выделяет только пустые флаги и проверяет поддержку записью нуля.
При CUDA_ERROR_NOT_SUPPORTED остаются обычные события. Входные данные и
результаты не кэшируются. Начальная версия не поддерживает OUTPUT_GRAPH
и CRT_PIPELINE. Эмуляция CPU сохраняет обычный путь; поведение драйвера
проверяется реальными GPU-прогонами и не имитируется локальной эмуляцией.
