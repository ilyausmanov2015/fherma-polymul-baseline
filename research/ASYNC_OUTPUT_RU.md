# Создание выходного vector параллельно с вводом

Обычный std::vector<uint32_t> требует инициализации элементов. Профиль
показал 128–148 мкс одного memset после упаковки и запуска GPU. Эксперимент
запускает resize свежего выходного vector на одном выделенном CPU в начале
run, одновременно с упаковкой и H2D. Возвращается тот же обычный владеющий
vector. Результаты и пустые выходные буферы между вызовами не сохраняются.

Worker создаётся до pin основного потока и использует последний разрешённый
CPU NUMA-узла GPU (на runner CPU23); пул копирования использует CPU0–15.
Всего 17 CPU для нашего кода. Данные задачи и завершение защищены mutex/CV.
До чтения data CPU явно ждёт resize; на исключении RAII ждёт worker до
уничтожения выходного vector. Исключение resize возвращается вызывающему.
Все затраты, включая пробуждение, выделение, обнуление и ожидание, в run.

Тест: 100 свежих выходов, сохранение прежних результатов, принудительный
length_error, исключение вызывающего во время работы. ThreadSanitizer
прошёл без сообщений о гонках. Вариант измеряется отдельно на обычном NTT,
с прежними четырьмя входными и восемью выходными частями.
