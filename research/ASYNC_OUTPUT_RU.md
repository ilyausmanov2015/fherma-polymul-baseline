# Создание выходного vector параллельно с вводом

Обычный std::vector<uint32_t> требует инициализации элементов. Профиль
показал 128–148 мкс одного memset после упаковки и запуска GPU. Эксперимент
запускает resize свежего выходного vector на одном выделенном CPU в начале
run, одновременно с упаковкой и H2D. Возвращается тот же обычный владеющий
vector. Результаты и пустые выходные буферы между вызовами не сохраняются.

Worker создаётся до pin основного потока и использует последний разрешённый
CPU NUMA-узла GPU (на runner CPU23); пул копирования использует CPU0–15.
Всего 17 CPU для нашего кода. Данные задачи и завершение защищены mutex/CV.
До чтения data CPU явно ждёт resize; на исключении RAII ждёт worker до
уничтожения выходного vector. Исключение resize возвращается вызывающему.
Все затраты, включая пробуждение, выделение, обнуление и ожидание, в run.

Тест: 100 свежих выходов, сохранение прежних результатов, принудительный
length_error, исключение вызывающего во время работы. ThreadSanitizer
прошёл без сообщений о гонках. Вариант измеряется отдельно на обычном NTT,
с прежними четырьмя входными и восемью выходными частями.

## Сигнализация через атомарные счётчики

FHERMA_OUTPUT_ALLOCATOR_SPIN заменяет CV-пробуждение на PAUSE/yield и
раздельные cache-line счётчики request/completed. Caller публикует указатель
на свежий vector и размер release-store; worker получает их acquire-load,
выполняет resize и публикует завершение release-store. Caller acquire-load
предшествует чтению vector или исключения. Одновременно существует ровно
одна задача. RAII, сохранение владения старыми результатами и exception
propagation прежние. В init создаётся только worker, без выходных векторов.

FHERMA_OUTPUT_ALLOCATOR_CPU_INDEX выбирает индекс в разрешённой NUMA-маске,
не глобальный номер CPU. Эксперимент использует индекс 16, после CPU-пула
0–15; если CPU меньше, используется последний разрешённый. Значение -1
сохраняет прежний выбор последнего CPU. На других cpuset отдельное ядро
не гарантируется. Affinity применяется только собственному worker.

Spin-вариант прошёл 100 свежих результатов, сохранение предыдущих выходов,
length_error и unwind caller под ThreadSanitizer локально (ARM).
GPU-профиль должен показать, помогает ли это перекрыть инициализацию
вектора с вводом; прежняя CV-версия ускорения не дала.

cc0151e: GPU 3/3 плюс прогревы, 410,636 мкс, CUDA CI успешен.
Worker CPU16 подтвердился. Resize занимает 155–170 мкс, большая часть
перекрывается вводом; ожидание allocation после enqueue всего 12–20 мкс.
Однако далее остаётся 106–121 мкс ожидания GPU и 116–124 мкс копирования
с ожиданиями частей. Общая скорость хуже синхронной версии, опция выключена.
