# Сохранение output placement при расширении input team

Полный physical-first уменьшал CPU packing, но увеличивал время вывода.
FHERMA_PHYSICAL_CORES=2 сохраняет первые OutputThreads-1 worker CPU
(caller участвует в выводе), затем размещает дополнительные input workers
по одному на оставшихся ядрах. На измеренной маске 0..23 и caller0 это
CPU1..7 для output workers и CPU8,10,12,14,16,18,20,22 для остальных.
Вывод и prefault по-прежнему используют CPU0..7; input team охватывает
12 ядер по topology runner вместо исходных восьми.

FHERMA_INTERLEAVED_INPUT назначает чётные rank входу A, нечётные B;
номер части внутри операнда rank/2. Это распределяет оба операнда между
плотной output-группой и дополнительными ядрами. Без чередования почти
весь A оставался бы на первых четырёх ядрах, ограничивая обе передачи.
Диапазоны каждой пары A/B по-прежнему непересекающиеся и покрывают весь
буфер, включая нечётные длины. SFENCE и completion handoff не меняются.

Эксперимент в отдельной ветке experiment/hybrid-copy. Гипотеза — сохранить
прежнюю скорость output и выиграть на input; измерений пока нет.
Чистый план размещения проверяет все 24 caller и 27 длин сохранённого
префикса, sparse masks, packages, unknown topology. Реальное применение
affinity и арифметика проверяются отдельно Linux CI и GPU.
